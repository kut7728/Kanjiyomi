## 결정 ID 규칙

| 접두어 | 용도 |
|---|---|
| F- | 기능 |
| D- | 조사 결정 |
| DS- | 화면 설계 |
| VD- | 시각 디자인 |
| TD- | 기술 |
| IM- | 구현 |
| TS- | 테스트 |
| RL- | 출시 |
| S- | 화면 |
| T- | 테스트 시나리오 |
| M- | 마일스톤 |
| R- | 조사 문서 |

결정 표의 "근거"에는 그 결정이 드러나는 코드 파일을 적습니다. 경로는 저장소 루트 기준입니다.

## 문서 변경 규칙

- 확정된 내용과 다르게 구현해야 하면 **문서를 먼저 고치고** 결정 ID를 남긴다.
- 사양·동작·화면·API·데이터 모델이 바뀌면 같은 작업 안에서 `docs/`를 갱신한다.
- 미정 항목은 '결정 대기'에 둔다.
- 미구현 기능은 완료로 쓰지 않는다.
- 코드와 문서가 다르면 코드를 사실로 보고, 문서를 고치거나 결정 대기에 올린다.

턴이 끝날 때 `docs/` 밖 파일만 바뀌었으면 훅(`.cursor/hooks/spec-docs.py`)이 문서 갱신을 한 번 요청합니다.
